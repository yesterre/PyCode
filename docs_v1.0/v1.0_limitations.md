# V1.0 局限与非目标

> 版本：PyCode V1.0  
> 目的：明确当前能力边界，避免把演示型 Agent harness 误解为完整生产级平台。

## 当前局限

- 主要支持 Python 项目；跨语言完整支持不在 V1.0 范围内。
- 调用关系来自静态 AST 和轻量图谱，不能完全覆盖动态调用、反射、运行时注入和复杂类型推断。
- 图谱保存为 JSON 文件，不使用图数据库或向量数据库。
- LLM 只解释 PyCode 选择出的有限上下文，不直接读取整个仓库。
- Memory 是辅助上下文，不是权威事实来源。
- 入口分析、影响范围和测试覆盖检查都是静态分析辅助结果，需要人工结合项目语义确认。
- Streamlit UI 是展示型 Demo，不是完整 IDE。

## V1.0 明确不做

- 不自动修改源代码。
- 不自动创建 commit、reset、push 或执行其它危险 git 操作。
- 不默认运行测试；只有显式 `--run-tests` 才允许受控测试工具运行。
- 不实现完整多 Agent 协作系统。
- 不实现远程 MCP、OAuth 工具授权或动态工具市场。
- 不实现后台 worker 或自动任务调度。
- 不把 Task DAG 升级为完整项目管理系统。
- 不引入大型外部依赖、图数据库或向量数据库。
- 不为展示效果伪造 Agent 能力。

## 安全边界

V1.0 的 Agent harness 默认是只读开发分析工具。工具调用必须经过 ToolSpec 注册和 policy 检查。权限拒绝、工具失败和 LLM fallback 都应进入 trace，成为可审计状态。

## 后续方向

后续版本可以考虑：
- 更精细的符号解析和跨文件调用关系。
- 更强的上下文预算和 evidence ranking。
- Agent run 报告导出。
- 更完整的 UI 图谱交互。
- 在清晰 policy 边界下扩展更多工具。

这些方向都应建立在 V1.0 已有的证据追踪和权限边界上。
