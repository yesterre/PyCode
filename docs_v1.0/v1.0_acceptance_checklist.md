# V1.0 验收清单

> 版本：PyCode V1.0  
> 阶段：V1.0-D  
> 日期：2026-07-14  
> 目标：用可重复的真实开发分析场景验证 Agent harness 的稳定性、可展示性和可解释性。

## 运行前准备

```powershell
.\.venv\Scripts\python.exe -m pycode.cli index .\examples\demo_project
.\.venv\Scripts\python.exe -m pycode.cli graph .\examples\demo_project
```

验收默认不依赖真实 LLM API。离线演示优先使用 `--rule-plan`；自动化测试中的 LLM 行为使用 fake client。

## P0 验收项

### 1. 入口分析

命令：

```powershell
.\.venv\Scripts\python.exe -m pycode.cli query entry .\examples\demo_project
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "这个项目的入口在哪里？" --plan-only --show-context --rule-plan
```

预期观察点：
- `query entry` 能识别 `main.py` 作为入口候选。
- Agent 输出包含 plan、todo、context、trace 和 evidence。
- `--show-context` 能展示 included / skipped context section。

通过标准：入口候选、Agent step、trace 和 context 均可解释入口判断来源。

### 2. 新手阅读顺序

命令：

```powershell
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "这个项目的入口在哪里？阅读顺序应该是怎样的？" --plan-only --show-context --rule-plan
```

预期观察点：
- task type 归类为 onboarding / entry 相关任务。
- evidence 能覆盖入口、controller、service、model 或测试文件线索。
- Todo 能反映阅读顺序分析的步骤完成状态。

通过标准：输出能从入口文件开始解释项目阅读路径，不依赖空泛总结。

### 3. 改动影响分析

命令：

```powershell
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "分析 services/user_service.py 的影响范围" --show-context --rule-plan
```

预期观察点：
- Agent 调用 graph / read / search / retrieve 类工具收集证据。
- evidence 中出现目标文件和相关依赖文件。
- final answer 说明影响范围来自图谱或检索结果。

通过标准：影响分析可追溯到文件关系，而不是只给自然语言判断。

### 4. Git Diff 风险

示例项目默认不携带 `.git`。需要真实 diff 时，复制示例项目到临时目录并初始化 git：

```powershell
Copy-Item .\examples\demo_project $env:TEMP\pycode_demo_git -Recurse -Force
git -C $env:TEMP\pycode_demo_git init
git -C $env:TEMP\pycode_demo_git add .
git -C $env:TEMP\pycode_demo_git commit -m "baseline"
Add-Content $env:TEMP\pycode_demo_git\services\user_service.py "# v1 acceptance marker"
.\.venv\Scripts\python.exe -m pycode.cli agent $env:TEMP\pycode_demo_git "当前 git diff 有什么风险？" --show-context --rule-plan
```

预期观察点：
- `changed_files` 能列出变更文件。
- `git_diff` 能返回 diff 摘要。
- 非 git 或无 diff 场景有清晰降级说明。

通过标准：有 diff 时能读取真实变更；无 diff 时不会静默失败。

### 5. 测试覆盖检查

命令：

```powershell
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "检查 services/user_service.py 的测试覆盖" --no-tests --show-context --rule-plan
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "检查 services/user_service.py 的测试覆盖并运行测试" --run-tests --show-context --rule-plan
```

预期观察点：
- `--no-tests` 下只定位相关测试文件，不执行 pytest。
- `--run-tests` 下才进入受控测试工具。
- policy / trace 能说明是否允许运行测试。

通过标准：测试执行边界与用户显式参数一致。

## P1 验收项

### 6. 工具失败恢复

预期观察点：
- 失败工具结果进入 `tool_results`。
- trace 记录失败状态、错误摘要和 turn。
- Todo 中对应步骤标为失败或保留可诊断状态。

通过标准：工具失败不会导致 Agent run 崩溃或丢失上下文。

### 7. Policy Denial

预期观察点：
- 未授权测试运行返回 `denied_by=policy`。
- trace 中能看到 policy decision。
- final / stop 语义清楚，不伪装成工具成功。

通过标准：权限拒绝是可观察结果，不是异常吞掉。

### 8. LLM Planner Fallback

预期观察点：
- LLM 返回无效 schema 时进入 fallback。
- trace 中出现 `LLMPlanFallback` 或 `LLMNextActionFallback`。
- Rich 输出展示 planner fallback reason。

通过标准：LLM 不稳定不会阻断离线规则路径或最终可解释输出。
