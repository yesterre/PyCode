# v1.0 开发记录规范

每当开启一个新阶段开发开始前，请你在 docs_v1.0 里新建一个md文档，专门用于存放该阶段的开发记录。
文档命名为 V1.0X_development_record.md , X 指ABCD四个阶段字母。

## 总体开发要求

开发时，在保障功能完善成熟时，尽可能减少所谓“兜底”“兼容”代码的实现！

## 开发前

请你在对应阶段文档中补充以下内容：
1.本阶段要完成的主要目标和内容，要达到的效果；
2.拆解这一阶段需要进行的工作，实现的功能，具体到各个具体文件;
3.解释一下为何要做这样的修改，修改的依据是什么（找到 CCLearning 笔记文件对应的知识和实现），即用专业的讲解解释这一步升级的理由。

## 开发中

请你在对应阶段文档中补充以下内容：
1.每完成或修改一块内容时，向文档中添加或修改一段简单的开发纪要，说明这一步动作做了什么；
2.要保留一块专门的区域，用于记录每次开发中出现的问题，例如报错等，需要总结问题；

### 开发后

请你在对应阶段文档中补充以下内容：
1.根据修改开发实际情况总结本阶段实际完成内容和完成情况；
2.总结后续该阶段可改进或升级的点；
3.针对这一阶段实现的内容，用一块专门的区域，用于简单明了地给出这一阶段各个已实现的功能或测试的具体运行方法（运行步骤、命令行指令等）。
