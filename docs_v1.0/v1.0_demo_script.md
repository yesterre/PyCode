# V1.0 演示脚本

> 适用版本：PyCode V1.0  
> 演示目标：展示离线可复现的代码理解、Agent loop、trace、todo、context 和边界行为。

## 1. 准备示例项目

```powershell
.\.venv\Scripts\python.exe -m pycode.cli index .\examples\demo_project
.\.venv\Scripts\python.exe -m pycode.cli graph .\examples\demo_project
```

观察点：
- 生成 `.pclens/index.json`。
- 生成 `.pclens/code_graph.json`。
- Rich 输出展示文件数、节点数和边数。

## 2. 静态入口查询

```powershell
.\.venv\Scripts\python.exe -m pycode.cli query entry .\examples\demo_project
```

讲解要点：
- PyCode 先用 AST 和图谱判断入口候选。
- 入口判断来自静态证据，不需要 LLM。

## 3. 离线 Agent 演示

```powershell
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "这个项目的入口在哪里？阅读顺序应该是怎样的？" --plan-only --show-context --rule-plan
```

讲解要点：
- `--rule-plan` 使用离线规则 planner，不调用真实 LLM。
- `--plan-only` 展示计划、Todo 和 Context，不执行工具。
- `--show-context` 展示哪些 context section 被包含或跳过。

## 4. 普通 Agent 分析

```powershell
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "分析 services/user_service.py 的影响范围" --show-context --rule-plan
```

讲解要点：
- Agent 会通过工具收集文件、图谱和检索证据。
- 输出中的 turns、trace、evidence 可解释最终结论。
- 这是开发分析 harness，不是自动改代码工具。

## 5. 测试覆盖边界

默认不运行测试：

```powershell
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "检查 services/user_service.py 的测试覆盖" --no-tests --show-context --rule-plan
```

显式授权后运行测试：

```powershell
.\.venv\Scripts\python.exe -m pycode.cli agent .\examples\demo_project "检查 services/user_service.py 的测试覆盖并运行测试" --run-tests --show-context --rule-plan
```

讲解要点：
- `--no-tests` 是只分析、不执行测试。
- `--run-tests` 才允许测试工具运行。
- 测试运行会进入 policy、trace 和 tool result。

## 6. Git Diff 风险演示

示例项目默认没有 `.git`，推荐复制到临时目录演示：

```powershell
Copy-Item .\examples\demo_project $env:TEMP\pycode_demo_git -Recurse -Force
git -C $env:TEMP\pycode_demo_git init
git -C $env:TEMP\pycode_demo_git add .
git -C $env:TEMP\pycode_demo_git commit -m "baseline"
Add-Content $env:TEMP\pycode_demo_git\services\user_service.py "# demo risk marker"
.\.venv\Scripts\python.exe -m pycode.cli agent $env:TEMP\pycode_demo_git "当前 git diff 有什么风险？" --show-context --rule-plan
```

讲解要点：
- `changed_files` 和 `git_diff` 读取真实 git 状态。
- 非 git 项目或无 diff 时应清楚降级。
- PyCode 不会自动提交、重置或推送 git。

## 7. LLM 演示

如果配置了 `.env` 或环境变量，可以运行普通问答：

```powershell
.\.venv\Scripts\python.exe -m pycode.cli ask .\examples\demo_project "这个项目的入口在哪里？"
.\.venv\Scripts\python.exe -m pycode.cli onboard .\examples\demo_project
.\.venv\Scripts\python.exe -m pycode.cli impact .\examples\demo_project services/user_service.py
```

讲解要点：
- LLM 只解释 PyCode 选出的有限上下文。
- LLM 不直接读取整个仓库。
- V1.0-D 自动化验收不依赖真实 LLM API。

## 8. UI 展示

```powershell
.\.venv\Scripts\streamlit.exe run .\ui\streamlit_app.py
```

观察点：
- 项目概览、文件树、图谱边、memory、tasks 可以读取 V1.0 schema。
- Agent run 展示 trace、todo、context 和 evidence。
- UI 是展示型 Demo，不是完整 IDE 或后台任务系统。
