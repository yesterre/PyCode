# PyCode 项目讲解稿

PyCode 是我围绕“代码库理解”和“开发任务分析”做的一个 Python Agent 项目。它的目标不是简单封装一个聊天接口，而是实现一层自己的代码理解中间层：先扫描项目、解析代码结构、构建代码图谱，再把这些结构化信息交给问答或 Agent 使用。这样做的好处是，回答不是纯靠大模型猜，而是能追溯到具体文件、函数、图谱关系和工具调用结果。

这个项目最初从一个很小的 MVP 开始，只做 Python 文件扫描和 AST 解析，能提取 import、class、function 并生成 index.json。之后我把数据结构升级成图谱，把文件、类、函数、方法作为节点，把包含、导入、调用关系作为边，保存成 code_graph.json。这样项目就不只是列清单，而是能回答“谁依赖谁”“入口可能在哪”“某个函数调用了什么”这类结构问题。

在接入 LLM 时，我没有让模型直接读取整个仓库，而是先通过检索器从 index 和 graph 中挑选相关上下文，再组织 prompt。这个设计是项目里比较关键的一点，因为代码库问答的核心不是把内容塞给模型，而是决定应该交给模型哪些代码、哪些图谱关系、多少上下文，以及如何保留证据位置。

后面我继续做了轻量 Agent 层。它会根据用户的开发任务规划工具调用，比如读取 git diff、搜索代码、查询图谱、读取文件或受控运行测试。Agent 默认只做分析和建议，不自动修改代码、不自动提交 git，也不默认运行测试。这个边界是有意保留的，因为当前阶段更关注可解释的开发分析流程，而不是不受控的自动改代码。

为了让 Agent 的过程更清楚，我又补了 Trace、Todo、Task DAG、Memory 和 Context Builder。Trace 记录工具调用过程，Todo 展示执行清单，Task DAG 保存带依赖的任务，Memory 保存项目级知识，Context Builder 把身份、工具、权限、证据和记忆分层组装。这样最终结果不只是一个回答，还能看到它为什么这么回答、调用过哪些工具、依据在哪里。

展示层目前有两种方式：Rich CLI 和 Streamlit Web Demo。Rich 让终端输出更适合演示，Streamlit 页面用来展示项目概览、文件树、代码图谱、Agent 运行结果、Memory 和 Task DAG。Web UI 不是完整 IDE，而是帮助别人快速理解项目能力的 Demo。

这个项目的技术取舍比较明确：解析层优先使用 Python 标准库 ast，图谱先用 JSON 文件保存，不急着引入 Neo4j；Agent 先做单 Agent + 多工具，不做复杂多 Agent；记忆先用 Markdown 和轻量 frontmatter，不做向量数据库。这样可以把复杂度控制在我能理解和解释的范围内，同时保留后续扩展空间。

当前局限也很清楚：它主要支持 Python 项目，静态 AST 分析无法覆盖所有动态调用和复杂类型推断；LLM 只能解释 PyCode 选择出的有限上下文；Agent 只做开发分析，不自动改代码。后续可以继续增强跨文件符号解析、方法调用解析、交互式图谱展示和 Agent 报告导出。

如果用一句话总结，PyCode 是我从零搭建的一个代码库理解与开发分析 Agent：它把代码先转成索引和图谱，再用可追溯的上下文和工具调用帮助理解项目、分析改动影响，并把 Agent 的计划、证据和执行过程展示出来。
